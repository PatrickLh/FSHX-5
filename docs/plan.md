# 风色幻想 5 资源提取与 Godot 重建计划

更新日期：2026-10-29

## 目标与边界

先完整保存原游戏资源，整理人物、背景、图标、人物动画及技能动效，并保留已拆分的故事；之后建立 Godot 工程，逐步重建人物、技能与场景。

当前 source 是游戏发行文件，不是完整引擎源码。资源包解压、资源名称恢复和 Godot 演出重建分别验收；不以“图片能打开”作为动画已还原的依据。不承诺全部原名、加密数据或三维骨骼能够恢复。二维帧可作建模参考，不能自动等价为完整三维模型。

## 当前目录与迁移

```text
original_resources/
  source/                     原 origin：压缩包、游戏本体，保持原内容
  unpacked/                   原 extracted：现有解包流，暂不删除或去重
  organized/
    characters/               人物立绘、表情、动作帧、动画描述
    backgrounds/              对话背景、过场图、场景图片
    effects/                  技能动画、粒子、特效贴图、演出配置
    models/                   原始模型与关联贴图
    ui/                       图标、界面图片、技能名牌
    audio/                    音乐、音效及技能音效引用
    story/                    原 story，保留已有拆分与分析文件
    legacy_assets/            原 assets，历史整理说明，待核验
  manifests/                  来源、校验、映射、缺口和迁移记录
godot/                        后续 Godot 工程及实际使用的转换资源
tools/                        解包、分析、导出、校验脚本
docs/                         本计划与分析文档
```

迁移时检查到：source 约 1.5 GB；unpacked 约 1.9 GB；story 约 53 MB。历史 assets 实际仅有 README，不能将其中所述立绘、模型等视为现有导出成果。精确迁移前后文件数和总字节数记录在 `original_resources/manifests/directory_migration.json`。

脚本路径已随迁移调整，从仓库根目录运行。现有脚本仍可能缺少历史中间数据；路径更新不表示管线已能完整执行。`.gitignore` 保留原先对原始包、解包流及 tools 的忽略策略，新增 Godot 缓存忽略；工具是否纳入版本控制后续单独整理。

## 阶段 0：目录整理（本次）

- [x] 原始发行文件、解包流及故事归入 original_resources。
- [x] 创建资源分类目录与独立 godot 目录。
- [x] 更新现有工具的目录引用、根 README 和忽略规则。
- [x] 保留历史资产说明，注明其与实际文件的差异。
- [x] 记录迁移前后文件数及总字节数。

验收：原有内容保留；资源和 Godot 代码位置清晰；本阶段不执行重新解包或重建工程。

## 阶段 1：建立可信的资源基线

- [ ] 扫描 source 中全部 JBF、散装图片、音频及 wrap，生成含相对路径、字节数、SHA-256 的 source_inventory.json。
- [ ] 审计现有解包脚本的容器边界、跳字节扫描逻辑及索引；确认 JBF 头部、记录间隔和尾部结构，避免将任意 zlib 命中当成真实资源。
- [ ] 对五个 JBF 在独立临时输出中重新解包，与当前 unpacked 按来源偏移、长度和哈希比较。
- [ ] 检查五位/六位编号及不同扩展名文件是否重复，区分旧输出、有效流和误识别；校验前不覆盖旧文件。
- [ ] 建立标准化流索引和失败报告，验证后再切换到标准输出，保存替换记录。

验收：每个输出可追溯到源包与偏移；重复、未知数据及未覆盖字节都有记录；磁盘文件数不直接充当资源数量。

## 阶段 2：图片解码与基础分类

- [ ] 根据文件头、尺寸、位深、压缩方式识别真实类型，区分标准 BMP、JPEG、模型文本、配置和未知流。
- [ ] 标准图片转为无损 PNG，保留原始流；非标准图片结合头部和上下文分析，逐类验证像素格式。
- [ ] 保留原始颜色版本，透明色和 alpha 转换另存派生版本，避免误删绿色等有效像素。
- [ ] 用动画定义、配置引用和缩略图联系表辅助分类人物、背景、图标、技能贴图及过场素材。
- [ ] 提取 source 内的散装图片和音频并记录来源。

验收：全部候选图像有解码状态；成功图片尺寸正确且可预览；无法判断的资源进入待确认清单，不强行归类。

## 阶段 3：人物与人物动画

- [ ] 从人物配置和现有故事索引建立角色 ID、姓名、头像引用表。
- [ ] 解析 Ani 动画资源与描述，导出帧引用、顺序、时长、偏移、锚点和可识别的方向信息。
- [ ] 恢复立绘、表情、行走、待机、攻击、受击、施法等动作关联，按实际数据补充动作类型。
- [ ] 将原名恢复的直接证据与顺序推断分开；每项记录证据和置信度，未知者保留稳定编号。
- [ ] 输出人物资源清单、动作预览及帧缺失报告。

验收：人物已确认资源可浏览；动画保留播放所需参数；未确认人物、动作和帧引用均可追踪。

## 阶段 4：背景、界面与原始模型

- [ ] 区分对话背景、过场图、海面动画、界面图和场景贴图，避免仅凭尺寸分类。
- [ ] 结合剧情或场景配置恢复背景名称与使用位置。
- [ ] 解析 XFile 中的模型、材质、贴图引用及可能存在的骨骼/动画数据；确认人物、怪物、场景物件和特效归属。
- [ ] 建立模型与贴图依赖清单，抽样验证坐标、比例、UV、透明材质和法线。
- [ ] 如需转换为 glTF/GLB，保留原始 .x，记录转换参数与损失。

验收：背景和 UI 有可视目录；模型依赖可解析；缺贴图或不支持的数据有明确记录。

## 阶段 5：技能动效关联与预览

- [ ] 扫描 GameData 中的技能演出、粒子及相关配置，以实际解析结果确认类型和数量。
- [ ] 建立“技能 ID → 演出脚本 → 动画/粒子 → 图片/模型 → 音效”的依赖图。
- [ ] 解析触发时间、位置、缩放、颜色、混合方式、镜头和人物动作；未知指令保留原文及位置。
- [ ] 按技能整理资源包、时间事件表、引用清单和缺失项；共享资源使用引用，避免重复复制。
- [ ] 选取近战、远程、粒子和模型特效等代表技能，制作组合预览并与游戏表现核对（有可用运行环境时）。
- [ ] wrap 数值表单独评估；不让其未知格式阻塞图像和演出资源整理，不将历史“加密”判断直接作为结论。

验收：可解析的技能依赖均已记录；明确区分“素材已提取”“参数已解析”“演出已验证”。

## 阶段 6：整体交付与覆盖审计

- [ ] 建立全局 resource_catalog.json：稳定 ID、源包/散装路径、流偏移、哈希、原名、分类、输出路径、关联 ID、证据、置信度及状态。
- [ ] 自动检查文件存在、图片解码、动画缺帧、模型缺贴图和配置未解析引用。
- [ ] 生成人物、背景、UI、技能的缩略图或预览目录。
- [ ] 输出 coverage.md 和 unresolved.json，分别列出已发现、已提取、已解码、已关联、已验证数量。
- [ ] 固化运行命令、依赖和版本，验证重复执行不会覆盖原件或产生无依据的重复资源。

验收：所有源文件和发现的资源都有处理状态；完整性以覆盖报告说明，不能把未识别资源算作成功。

## 阶段 7：Godot 最小验证与后续重建

- [ ] 确定 Godot 版本及二维、三维或混合路线，建立 project.godot 和最小测试场景。
- [ ] 先验证一名角色的一组动作、一个背景及一个技能，确认资源格式和坐标约定。
- [ ] 在独立建模工具中创建或修复人物、骨骼、动作和场景资产，再导入 Godot；原有模型可复用程度逐项核验。
- [ ] 在 Godot 重建粒子、材质、镜头和技能时间编排，以原始演出资料作为参考。
- [ ] 将故事转换为运行时对话数据，逐步接入场景与角色。
- [ ] 最小验证通过后扩展全部人物、技能与场景；转换结果放入 godot，原始资料保留在 original_resources。

验收：最小场景可运行并展示角色、背景、技能和对话，再进入批量制作。

## 执行顺序与缺口处理

依次执行阶段 1—6，阶段 3—5 均以可靠索引和图片解码为基础；提取阶段完成后再开展阶段 7。先用小样本验证格式与映射，再批量处理。

当前主要不确定项：历史导出成果缺失、解包重复、部分图像格式未知、无名流的归属、动画和演出参数、wrap 数据格式。每个问题记录证据、影响范围与下一步处理方式，不通过猜测掩盖缺口。暂不删除旧解包数据，不自动执行历史中会覆盖故事成果的脚本。
